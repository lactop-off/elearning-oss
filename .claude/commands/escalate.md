# /escalate

`/build-with-gates` がループ上限に達した、または停滞検出された場合に、人間が判断するための情報を整理します。

引数: $ARGUMENTS

## 出力フォーマット

```markdown
# ⚠️ 人間の判断が必要

## 問題の要約
$ARGUMENTS

## 試行した内容
1. <イテレーション 1 で試したこと>
2. <イテレーション 2 で試したこと>
3. ...

## 現在の状態
- 残っている Gate FAIL: ...
- 主要な指摘 (まだ解決できていない):
  - [ファイル:行] 内容
  - ...

## なぜ自動で解決できなかったか (推定)
- 仕様の曖昧さ (具体的に: ...)
- 既存コードの構造的問題 (具体的に: ...)
- ドメイン知識が必要 (具体的に: ...)
- ライブラリ・ツール側の問題 (具体的に: ...)

## 候補となる対応 (人間が選ぶ)
### 案 A
- 内容: ...
- メリット: ...
- デメリット: ...
### 案 B
- 内容: ...
- メリット: ...
- デメリット: ...

## 推奨
おすすめは案 X です。理由: ...

## 人間に依頼したいこと
- [ ] 仕様の確認: ...
- [ ] 構造的な意思決定: ...
- [ ] 例外的な対応の許可: ...
```

## 用途

- 自動ループで詰まった時の情報整理
- レビュアー / メンバーへの相談用テンプレート
- 「なぜできないか」を構造化して伝える
